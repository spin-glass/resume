## 未着手機能

### 20. UX改善 (Post-Migration UX Improvements)

**優先度**: 最高
**目的**: Astro移行により消失したナビゲーション機能(TOC, Header)を復刻・改善し、長文ドキュメントの閲覧体験を向上させる。

#### 課題と背景 (Nextra版との差分)
1.  **ナビゲーション (Sidebar / TOC) の欠如**
    -   Nextra版にあったサイドバー(遷移)と目次(TOC)がなくなり、長い履歴書(resume-ja.qmd)でのランダムアクセスが困難。
2.  **ヘッダーリンクの消失**
    -   GitHub/SNSへの導線や言語切り替えスイッチがなく、回遊性が低下。
3.  **モバイル対応の不足**
    -   レスポンシブではあるものの、ハンバーガーメニュー等のナビゲーションがない。

#### 機能要件
1.  **追従型 目次 (Sticky TOC)** (FR-UX01)
    -   Desktop: 右サイドバーに常時表示
    -   Mobile: 開閉式または下部固定でセクションジャンプ機能を提供
2.  **グローバルヘッダーの実装** (FR-UX02)
    -   サイトロゴ、GitHubリンク、言語切り替えスイッチ(i18n連携)を配置
    -   スクロール時のSticky/Hide挙動の最適化
3.  **モバイルナビゲーション** (FR-UX03)
    -   ハンバーガーメニューの実装、またはボトムナビゲーションによる回遊性確保


### 19. Meta-Portfolio (本リポジトリの提示プロジェクト化)

**優先度**: 最高
**目的**: 「履歴書を管理するシステム」そのものを、最高のポートフォリオとして機能させる。コードの品質、設計思想、開発プロセスを「見せる」ための仕組みを構築する。

#### 背景
外部に公開しているプロダクトだけでなく、このリポジトリ自体の「Spec駆動開発」「モノレポ管理」「LLM統合」の実践状況が、エンジニアとしての最高のアピール材料になる。

#### 機能要件
1.  **Repository Design Doc の公開** (FR-META01)
    -   本リポジトリがどのように設計され、なぜこの技術選定（Astro, LangGraph等）をしたかの解説ページ
2.  **Development Workflow の可視化** (FR-META02)
    -   Cursor/Geminiとどのように対話し、どのようにSpecからコードを生成しているかの「開発プロセスのデモ」
3.  **セルフレビュー・エージェントの展示** (FR-META03)
    -   `resume-review` パッケージが自分自身の履歴書をどう改善したかの「Before/After」および思考プロセスのログを可視化して展示


### 21. Portfolio Planning Agent (ポートフォリオ提案エージェント)

**優先度**: 最高
**目的**: 求人要件と現状のスキルのギャップを分析し、「何を開発すればそのギャップを埋められるか」というポートフォリオ案を自動で提案・起案するエージェント機能を実装する。

#### 機能要件
1.  **Skill Gap Analysis** (FR-PPA01)
    -   履歴書(resume-ja.qmd)と、目指すJob Descriptionを比較し、不足している経験領域(Agents, MLOps等)を特定する。
2.  **Portfolio Ideation** (FR-PPA02)
    -   特定されたギャップに対し、それを埋めるための具体的なアプリケーション開発案を生成する。
3.  **Roadmap Integration** (FR-PPA03)
    -   生成された案をユーザーが承認した場合、自動的にこの `docs/roadmap.md` やタスクリストに追記するワークフローを構築する。


### 18. エージェントの信頼性向上・評価基盤 (Agent Reliability & Evaluation)

**優先度**: 高
**目的**: 現在のAIエージェントによるレビューや修正が、期待通り適切に行われているかを定量的・客観的に検証する仕組みを構築する。

#### 背景
現状、エージェントの出力（職務経歴書の修正内容など）が適切であるかの自動テストが存在せず、品質が保証されていない。一般的なNLP/LLM評価手法を導入し、改善サイクルを回せるようにする。

#### 機能要件
1.  **ゴールデンデータセットの作成** (FR-AGE01)
    -   正解となる修正例やレビューコメントのセットを作成
2.  **LLM評価の導入 (LLM-as-a-Judge)** (FR-AGE02)
    -   Ragas や LangSmith 等を活用し、エージェントの修正内容を別のLLMが客観的に評価する仕組みの構築
3.  **エージェントノードのユニットテスト** (FR-AGE03)
    -   LangGraph の各ノード（State遷移、ツール呼び出し）に対する Jest/Pytest による自動テストの実装
4.  **回帰テストパイプライン** (FR-AGE04)
    -   プロンプト変更時に、全体の出力品質が低下していないかを確認する評価ジョブのCI統合


### 17. Visual Reinforcement & Data Visualization (ビジュアル強化とデータ視覚化)

**優先度**: 中
**目的**: 経歴やスキルセットを単なるテキストや表ではなく、視覚的にインパクトのある形式（チャート、タイムライン、図解）で表現し、「一目で伝わる」履歴書にする。あわせて、どの表現が採用担当者に効果的かの検証も行う。

#### 機能要件
1.  **Effectiveness Verification** (FR-VIS01)
    -   採用担当者の視点（短時間での理解）において、テキスト対比でどの程度の理解度向上・印象改善があるかをA/Bテストやヒアリングで検証する。
2.  **Career Timeline & Interactive Charts** (FR-VIS02)
    -   職歴の時系列をスクロールと連動して表示するインタラクティブなタイムライン。
    -   スキルセットの習熟度と使用期間を掛け合わせた多角的なチャート表示。
3.  **Aesthetic Polish (Visual Impact)** (FR-VIS03)
    -   「プレミアムな」印象を与えるためのマイクロインタラクション、トランジション、タイポグラフィの強化。
    -   Shadcn UI / Tremor などを活用したモダンで洗練されたUIコンポーネントの導入。

## ドキュメントガバナンス

### ドキュメントカテゴリ

| カテゴリ | 配置場所 | 目的 | 備考 |
|---------|---------|------|------|
| **ガイド** | ルート直下 | 開発者向け指示・規約 | `README.md`, `CLAUDE.md` |
| **ロードマップ** | `docs/roadmap.md` | 開発計画・ステータス | |
| **機能仕様** | `specs/{NNN}-{name}/` | 開発中機能の詳細設計 | 完了後は `contracts/` 以外アーカイブ扱い |
| **パッケージDoc** | `packages/*/README.md`| パッケージの使い方 | |
| **コンテンツ** | `resume/` | 履歴書ソース(Product) | `resume-ja.qmd` が正本 |
| **メタデータ** | `.specify/` | プロジェクト管理テンプレート | 開発プロセスを定義 |

### コンテンツガバナンス (Resume)

1. **正本 (Single Source of Truth)**
   - `resume/resume-ja.qmd` が唯一の正本です。
   - 内容の修正は必ずこのファイルに対して行ってください。

2. **生成ファイル (Generated Artifacts)**
   - 以下のファイルは `pnpm resume:build` または `pnpm sync` で自動生成されます。手動編集しないでください。
     - `packages/web/pages/ja/index.mdx`
     - `resume/output/*.pdf`
     - `resume/output/*.html`

3. **一時ファイル**
   - `resume/review_*/` ディレクトリはAIレビューの実行ログです。Gitにはコミットされません（`.gitignore` 設定済み）。

### 新機能追加時のルール

1. `docs/roadmap.md` に概要を追記
2. `specs/{NNN}-{name}/` に詳細仕様を作成
   - 必須: `spec.md`, `plan.md`, `tasks.md`
   - 任意: `data-model.md`, `research.md`, `quickstart.md`, `contracts/`
3. 完了後、`CLAUDE.md` に要点を反映
4. `docs/roadmap.md` のステータスを更新
