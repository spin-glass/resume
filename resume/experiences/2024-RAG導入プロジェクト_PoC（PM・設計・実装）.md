# Situation
社内に蓄積された膨大なドキュメントやナレッジ（社内規定、技術マニュアル、過去の議事録など）の検索・活用を高度化するため、LLMを用いたRAG（Retrieval-Augmented Generation）システムの技術検証（PoC）プロジェクトが発足しました。エンジニア3名を含む計6名のチームにおいて、実用化に向けた精度検証と最適なシステム構成の選定が求められました。

# Task
プロジェクトマネージャー（PM）兼リードエンジニアとして、設計から実装、評価設計までの全フェーズを牽引しました。主なミッションは、RAG特有の課題である「検索精度の低さ」と「回答の不正確さ（ハルシネーション）」を解消し、本番導入に向けた定量的な判断基準を確立すること、およびステークホルダーに対して技術的妥当性を証明することでした。

# Action
技術的な精度向上と運用監視の両面から、以下の施策を講じました。

- **RAGパイプラインの設計・実装**: 
    - Amazon Bedrock（Claude 3 Sonnet/Haiku）を基盤とし、LangChainを用いた柔軟なRAGアーキテクチャを構築。
    - **前処理の高度化**: 表形式のExcelやレイアウトの複雑なPDFに対し、生成AIを用いてMarkdown形式に構造化・標準化する前処理パイプラインを実装。テキスト抽出精度を向上させることで、検索精度（Retrieval）の底上げを実現。
    - **メタデータフィルタリングの導入**: クライアントの業務フローを分析し、ドキュメント種別や業務カテゴリごとのメタデータ（タグ）をBedrock Knowledge Baseに付与。検索時に適切なフィルタリングを行うことで、ノイズを排除し回答精度を向上。
    - **チャンク分割の工夫**: 文脈の分断を防ぐため、意味的なまとまりで分割するセマンティック分割（Semantic Chunking）などの手法を検証・導入。
- **評価基盤とオブザーバビリティの構築**:
    - **Ragasによる定量評価**: LLMによる自動評価指標（Faithfulness, Context Relevancy, Answer Relevancy）を導入。感覚的な評価ではなく、データに基づいた精度改善サイクルを確立。
    - **LangFuseによるトレーシング**: プロンプトの実行ログ、各ステップのレイテンシ、トークンコストを可視化。どの工程で回答精度が低下しているかを即座に特定できるデバッグ環境を整備。
- **PMとしてのリード**:
    - 非技術者のステークホルダーに対し、LLMの特性や限界を考慮した期待値調整を実施。
    - 検証用のQAを用意してもらうなど、課題管理を行いつつクライアントとのコミュニケーションを円滑に。

# Result
- **定量的な精度改善**: Ragasを用いた評価において、Markdown化とメタデータフィルタリング導入前と比較してContext Relevancy等の指標が大幅に向上することを確認。
- **高品質な回答生成**: 引用元の明示機能と合わせ、ビジネス用途で十分に実用可能な回答精度であることを実証。
- **プロジェクトの進展**: 構築した評価基盤により、プロンプト変更による影響を即座に数値化できる体制を構築。技術的実現可能性を明確に示したことで、本番導入に向けた意思決定を迅速化させました。
