# Situation
社内に蓄積された膨大なドキュメントやナレッジ（[要確認：社内規定、技術マニュアル、過去の議事録など]）の検索・活用を高度化するため、LLMを用いたRAG（Retrieval-Augmented Generation）システムの技術検証（PoC）プロジェクトが発足しました。エンジニア3名を含む計6名のチームにおいて、実用化に向けた精度検証と最適なシステム構成の選定が求められました。

# Task
プロジェクトマネージャー（PM）兼リードエンジニアとして、設計から実装、評価設計までの全フェーズを牽引しました。主なミッションは、RAG特有の課題である「検索精度の低さ」と「回答の不正確さ（ハルシネーション）」を解消し、本番導入に向けた定量的な判断基準を確立すること、およびステークホルダーに対して技術的妥当性を証明することでした。

# Action
技術的な精度向上と運用監視の両面から、以下の施策を講じました。

- **RAGパイプラインの設計・実装**: 
    - Amazon Bedrock（[要確認：Claude 3 Sonnet/Haiku等]）を基盤とし、LangChainを用いた柔軟なRAGアーキテクチャを構築。
    - チャンク分割戦略の最適化：単純な固定長分割だけでなく、文脈を維持するためのセマンティック分割（Semantic Chunking）を比較検証し、情報の欠落を最小化。
    - リトリーバル精度の改善：Embeddingモデルの選定に加え、検索結果のTop-K調整や、リランキング（Re-ranking）技術の導入検討により、ノイズを排除し関連性の高い文脈のみをLLMに渡すよう調整。
- **評価基盤とオブザーバビリティの構築**:
    - **Ragasによる定量評価**: LLMによる自動評価指標（Faithfulness, Context Relevancy, Answer Relevancy）を導入。感覚的な評価ではなく、データに基づいた精度改善サイクルを確立。
    - **LangFuseによるトレーシング**: プロンプトの実行ログ、各ステップのレイテンシ、トークンコストを可視化。どの工程で回答精度が低下しているかを即座に特定できるデバッグ環境を整備。
- **PMとしてのリード**:
    - 非技術者のステークホルダーに対し、LLMの特性や限界を考慮した期待値調整を実施。
    - PoCから本番運用を見据えたインフラ構成（AWS S3連携等）およびコスト試算を含むロードマップを策定。

# Result
- **定量的な精度改善**: 評価指標（Context Relevancy）において、初期ベースラインから25%の精度向上を達成。
- **高品質な回答生成**: 回答の忠実性（Faithfulness）で90%以上のスコアを記録し、ビジネス用途で許容可能なハルシネーション抑制レベルであることを証明。
- **プロジェクトの進展**: 構築した評価基盤により、プロンプト変更による影響を即座に数値化できる体制を構築。技術的実現可能性を明確に示したことで、本番導入に向けた意思決定を迅速化させました。
