# Situation
企業間マッチングシステムの成長に伴い、バックエンドのパフォーマンス向上と、システム稼働状況やユーザー行動を定量的に把握するためのデータ基盤整備が急務となっていました。当時はログが散在しており、障害発生時の原因特定や、サービス改善のためのデータ分析に時間を要しているという課題がありました。[要確認：チーム規模は5〜10名程度の開発体制を想定]。

# Task
機械学習エンジニア兼バックエンドエンジニアとして、以下のミッションを遂行しました。
1. FastAPIを用いたバックエンドAPIの機能改善およびパフォーマンス最適化。
2. 膨大なログデータを効率的に収集・蓄積し、即座に検索・分析可能にするデータパイプラインの構築。
3. 障害検知の迅速化を目的とした、エラー監視・通知フローの自動化。

# Action
バックエンドの堅牢化と、AWSのサーバーレスサービスをフル活用したデータ基盤構築に注力しました。

- **バックエンドAPIの改善**:
  - FastAPIの非同期処理（async/await）を最適化し、スループットを向上。
  - Pydanticを用いた厳密なスキーマ定義により、データの整合性確保とAPIドキュメントの自動化を推進。
- **サーバーレス・ログパイプラインの構築**:
  - アプリケーションログを **AWS Kinesis Data Firehose** を介して **S3** へリアルタイムに転送するパイプラインを実装。
  - **Amazon Athena** を導入し、S3上の生ログに対して標準SQLで直接クエリを実行できる環境を整備。パーティション設計を最適化することで、クエリの高速化とスキャンコストの削減を両立。
- **監視・通知基盤の整備**:
  - **CloudWatch Logs/Alarms** を設定し、特定のエラーパターンや閾値超過を検知した際に **Lambda** を介して即時通知（Slack等）を行う仕組みを構築。
  - Athenaを用いた定期的なログ集計クエリを設計し、システムの利用傾向を可視化するダッシュボードの土台を作成。

# Result
- **分析環境の劇的改善**: 従来、手作業で集計していたシステム利用データの分析が、AthenaによるSQL操作のみで即座に完了する環境を実現。
- **運用効率の向上**: ログ収集・分析基盤の整備により、障害発生時の調査時間が大幅に短縮され、運用負荷を軽減。
- **安定稼働の実現**: エラー監視体制の強化により、深刻な事象に発展する前の予兆検知が可能となり、システムの可用性が向上。
- **データ駆動型開発の促進**: ログクエリ設計を通じて、ユーザー行動に基づいた機能改善提案が可能になるなど、ビジネスサイドへの意思決定支援に貢献。
